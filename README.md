# Tab Reuse · 复用标签页

打开链接时优先回到已有标签页，需要独立页面时也能强制新开。适合反复打开同一份文档、工作台或网页应用的场景。

A lightweight Manifest V3 extension for desktop Chromium browsers that reuses existing tabs by URL and lets you explicitly open a separate tab.

## 能做什么

- **自动复用重复链接**：在普通新标签页地址栏输入已有链接，或通过网页链接新开相同地址时，关闭这次新建的重复页，切换到已有页。已有页不会被主动刷新。
- **优先复用**：从工具栏面板输入链接，点击「优先复用」或按 Enter；找到相同链接就切换过去，没有则创建新页。
- **强制新开**：从面板点击「强制新开」，保留独立标签页，即使已有相同链接。
- **链接右键菜单**：可直接选择「Tab Reuse：优先复用已有标签页」或「Tab Reuse：强制新开标签页」。
- **后台不抢焦点**：自动处理后台打开的重复页时，不主动切走当前页面或窗口。手动点击「优先复用」会切换到目标页。
- **随时暂停**：关闭「自动复用新打开的重复链接」后，面板按钮和右键菜单仍可使用。

自动复用发生在新标签页开始导航之后：它依赖浏览器的标签页事件合并重复页，**不是网络请求拦截器**。重复页可能短暂出现，也可能已经发出请求。希望先查找已有页、再决定是否访问时，请使用面板或右键菜单中的「优先复用」。

## 安装

日常使用不需要 Node.js、Python 或 `npm install`，只需加载扩展目录。

1. 下载或克隆本仓库；也可以解压构建生成的 `dist/tab-reuse-1.1.0.zip`。
2. 打开浏览器的扩展管理页。Chrome 和 Ego Lite 可输入 `chrome://extensions`；Edge 可输入 `edge://extensions`。
3. 开启「开发者模式」，点击「加载已解压的扩展程序」或「加载未打包的扩展程序」。不同浏览器的名称可能略有差异。
4. 如果使用源码，选择仓库中的 **`extension` 文件夹**；如果使用 ZIP，选择解压后的 **`tab-reuse` 文件夹**。所选文件夹内应直接包含 `manifest.json`，不要选择仓库根目录或 ZIP 文件。
5. 将 **Tab Reuse · 复用标签页** 固定到工具栏。

更新本地文件后，在扩展管理页点击该扩展的「重新加载」。安装、更新或重新加载扩展都不会主动整理之前已打开的标签页。

## 匹配规则和处理范围

只匹配浏览器规范化后的**完整 HTTP(S) URL**。协议、路径、查询参数及其顺序、`#` 片段都参与比较，不会移除追踪参数或猜测两个地址是否指向同一内容。不支持带用户名或密码的 URL。

| 两个链接的差别 | 是否视为相同链接 |
| --- | --- |
| `/page?id=1` 与 `/page?id=2` | 否 |
| `/page?a=1&b=2` 与 `/page?b=2&a=1` | 否 |
| `/page#one` 与 `/page#two` | 否 |
| `http://example.com/` 与 `https://example.com/` | 否 |
| `https://example.com` 与 `https://example.com/` | 是，URL 规范化后的地址相同 |

查找范围是扩展可见的**同一浏览器个人资料（profile）**。有多个匹配页时，优先选择同一窗口，其次是已激活的页面和浏览器提供的最近访问顺序。不会跨 profile 查找，扩展也不在无痕窗口启用。浏览器自带工作区或任务空间的可见范围取决于其扩展 API 实现。

自动复用只跟踪扩展运行后新建标签页的首次 HTTP(S) 导航，包括新建普通空白标签页后在地址栏输入链接。**已有页面的地址栏导航、站内跳转、刷新、前进和后退不会触发自动合并**，也不会批量清理历史重复页。

以下情况会保留新页：固定页、已从内存中丢弃的页，以及浏览器通知扩展时已经完成加载的非空白页。浏览器启动后的前 10 秒暂停自动处理，以减少对会话恢复的干扰；首次导航开始超过 15 秒后停止自动合并，避免迟到的事件关闭已经开始使用的页面。

## 浏览器兼容性

目标环境是 **Chromium 102+ 的桌面浏览器**，并且需要完整支持 Manifest V3 扩展，以及本项目使用的 `tabs`、`windows`、`storage.session`、`contextMenus` 和相关运行时 API。仅使用 Chromium 内核并不代表浏览器一定兼容；移动浏览器、裁剪过扩展能力的浏览器不在兼容承诺内。

| 浏览器 | 验证状态 |
| --- | --- |
| Ego Lite 0.5.1.11 | 已对扩展 **1.0.0** 版进行实机验证；不代表 1.1.0 已完成实机回归 |
| Chrome、Microsoft Edge、Brave | 按桌面 Chromium 扩展 API 预期兼容，尚未实机验证 |
| Opera、Vivaldi | 待验证；尤其需要检查各自新标签页地址和标签事件的差异 |

浏览器的自定义新标签页、第三方新标签页扩展和工作区功能可能影响自动识别，不能将某个浏览器的测试结果直接推广到其他浏览器。

## 开关、权限与数据

自动复用默认开启，开关保存在本机。关闭后再重新开启，不会回头清理暂停期间打开的标签页。

| 权限 | 用途 |
| --- | --- |
| `tabs` | 读取标签页 URL 以查找相同链接；扩展通过标签 API 切换、创建和关闭标签页 |
| `storage` | 保存本地开关及当前浏览器会话中的跟踪状态 |
| `contextMenus` | 提供链接右键菜单 |

没有网页内容脚本、主机权限、远程代码、分析统计或数据上传。会话状态使用 `storage.session`，可在后台 service worker 休眠后恢复；浏览器重启、扩展重新加载或停用时会清除。扩展不读取网页正文。

## 常见问题

**为什么相同页面没有合并？**

先检查完整 URL 是否一致、自动复用是否开启，以及两个标签页是否在同一 profile。已有页面上的地址栏跳转、强制新开的页、启动保护期内打开的页等都不会自动合并。浏览器自定义新标签页也可能需要单独适配。可以使用面板「优先复用」主动查找。

**浏览器原生「在新标签页打开」、Ctrl/Cmd + 点击或中键能强制保留一份吗？**

这些仍属于普通新标签页打开方式，会参与自动复用。需要保留独立页面时，请使用本扩展的「强制新开」按钮或对应右键菜单；也可以暂时关闭自动复用。

**会关闭我已经打开的页面，或丢失其滚动位置吗？**

自动合并只关闭本次跟踪到的新重复页，已有目标页不会被关闭或主动刷新。浏览器对已休眠页面的恢复行为仍由浏览器自身决定。

**为什么地址相同的页面闪了一下，甚至已经加载？**

自动处理在导航开始后才收到标签事件，无法保证请求尚未发出。面板或右键菜单的「优先复用」会先查找，再决定是否创建新页。

**支持清理所有重复标签页吗？**

目前没有批量清理功能。它关注之后新打开的链接，保留已有标签页的状态。

## 开发与打包

测试需要 **Node.js 20+**；打包另外需要 **Python 3**。项目没有 npm 依赖，无需先运行 `npm install`。

```bash
npm test
npm run pack
```

测试使用 Node.js 内置测试运行器及模拟浏览器 API，覆盖 URL 匹配、复用、新开、焦点、暂停和导航边界等行为。单元测试不能替代各浏览器的实机验证。

打包结果为 `dist/tab-reuse-1.1.0.zip`，其中 `tab-reuse/` 目录直接包含 `manifest.json` 和运行扩展所需文件。

```text
tab-reuse/
├── extension/           # 加载这个目录即可使用
│   ├── manifest.json
│   ├── background.js    # 浏览器事件、消息和右键菜单
│   ├── core.js          # URL 匹配与标签页复用逻辑
│   └── popup.*          # 工具栏面板
├── tests/               # 单元测试及开发辅助文件
├── scripts/package.py   # 生成可分发 ZIP
├── dist/                # 本地打包产物
├── package.json
└── README.md
```

API 参考：[Chrome tabs](https://developer.chrome.com/docs/extensions/reference/api/tabs)、[Chrome storage](https://developer.chrome.com/docs/extensions/reference/api/storage)、[Chrome contextMenus](https://developer.chrome.com/docs/extensions/reference/api/contextMenus)、[Microsoft Edge 扩展文档](https://learn.microsoft.com/en-us/microsoft-edge/extensions/)。
